# ADR-0005: ADR フォーマットに Status と結果・影響を足す

- Status: Accepted
- Date: 2026-05-24

## 目的

資料（`src/document.md`）と本リポジトリが用いる ADR フォーマットを、決定の瞬間に偏った軽量版から、ライフサイクルと結果も扱える形へ更新するかを決定する。

## 背景

[ADR-0001](0001-adr-management.md) で採用した「資料の5節（目的/背景/前提/選択肢/結論）＋ 薄いヘッダ（Status/Date）」について、外部からの指摘（issue #70）で内部矛盾が判明した。資料はスライドで ADR の価値を2つ挙げている（将来の参照／変更時に何を考慮すべきか）が、後者は Consequences の領分であるにもかかわらず専用の枠が無く、結論の「デメリットへの対処」に畳み込まれるだけだった。前向きの「この決定が生む新たな制約・取れなくなる選択肢」を取りこぼし、自ら掲げた目的②を形式が構造的に保証していない。

## 前提

- 「最低限から始める」方針（ADR-0001）は維持する。MADR 相当へのフルスペック化はしない。
- 教材スライドとドッグフーディング側のテンプレートは一致させる。
- Accepted な ADR の本文は immutable（ADR-0001）。既存 0001〜0004 へ遡及して節を足さない。

## 選択肢

- A. 結論の指示文だけ拡張（最小）… ⊕ 枠を増やさない ⊖ 前向きの新制約が依然「結論」に埋もれ、目的②の構造的担保にならない
- **B. 専用の「結果・影響」節を新設 ＋ Status を必須化（採用）** … ⊕ 目的②を構造で担保 ⊕ Y-Statements 系譜の軽さを保てる ⊖ 節が1つ増える
- C. MADR 相当へ拡張（Decision Drivers の独立項目化など）… ⊖ 規模に対して肥大化。issue #70 のスコープ外

## 結論

**B を採用。** Status・Date を必須化し、5節に「結果・影響」を加えた6節 ＋ ヘッダとする。判断基準（Decision Drivers）の独立項目化は見送る。教材（`src/document.md`）とテンプレート（`docs/adr/templates/template.md`）の双方を更新済み。

本 ADR は ADR-0001 が定めた**形式の改訂**であり、配置（`docs/adr/`）とツール（自前 zero-dep スクリプト）の決定は ADR-0001 のまま有効なので supersede はしない。

## 結果・影響

- 今後の ADR はすべて「結果・影響」節を持つ（本 ADR がその最初の実例）。
- 既存 ADR-0001〜0004 は immutable のため「結果・影響」節を持たない。形式の世代差が残るが、遡及改変しない方針を優先する。
- フォーマットをさらに増やしたくなったときは、肥大化（MADR 化）への歯止めとして本 ADR の「最低限維持」判断を参照すること。それを覆すなら本 ADR を supersede する。
- スクリプトは節追加に透過的（`create` はテンプレートをコピーするのみ）なので、追加の保守コストは発生しない。
